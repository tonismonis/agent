# CRM for friends — v1 spec (LOCKED 2026-08-02)

Locked synthesis of the wayfinder map [#1](https://github.com/tonismonis/agent/issues/1). Each section links its deciding ticket; the ticket holds the full rationale. Vocabulary: [CONTEXT.md](../../CONTEXT.md). Changes after this date require reopening the relevant decision, not editing in place.

## Product

Chat-only CRM for invited freelancer friends (e.g. a psychologist). No forms — a TanStack AI code-mode agent turns natural-language chat into data operations against a fixed schema. Spanish-friendly; Chile-only v1.

- Proven core: chat → agent-written TS → typed tools → Postgres round-trip, incl. multi-entity onboarding in one utterance ([#4](https://github.com/tonismonis/agent/issues/4), asset `crm/` @ 57c7a88).
- Chat is the only input; code mode's generative UI covers on-demand visualization ([#2](https://github.com/tonismonis/agent/issues/2)).

## Architecture

One shared multitenant service ([#9](https://github.com/tonismonis/agent/issues/9), [ADR-0002](../adr/0002-shared-multitenant-service.md)):

| Layer | Choice | Ticket |
|---|---|---|
| App | TanStack Start (React) + drizzle/pg + @tanstack/ai; scaffold via `tanstack create` add-ons `drizzle,tanstack-query,ai --no-examples` | [#3](https://github.com/tonismonis/agent/issues/3) |
| Agent | TanStack AI code mode: model writes TS in no-network sandbox composing `external_*` tools; SQL host-side in `.server()` impls | [#2](https://github.com/tonismonis/agent/issues/2) |
| Auth | Clerk, free Restricted mode (invite-only), magic links, networkless JWT verify; exit path = Better Auth | [#11](https://github.com/tonismonis/agent/issues/11) |
| Hosting | Render: one always-on Web Service (2 GB Standard) + Render Postgres same region; `drizzle-kit migrate` pre-deploy hook | [#12](https://github.com/tonismonis/agent/issues/12) |
| LLM | OpenRouter via `@tanstack/ai-openrouter`, one operator server key, ZDR-pinned (below) | [#13](https://github.com/tonismonis/agent/issues/13) |

## Tenancy + isolation

- Owner = isolation root; one Clerk identity ↔ one Owner; no workspace layer ([#9](https://github.com/tonismonis/agent/issues/9)).
- Every Owner-owned relation carries `owner_id`; transaction-local RLS (`SET LOCAL`) + non-bypass app role + Owner-scoped FKs. Proven 11/11 scenarios ([#14](https://github.com/tonismonis/agent/issues/14), `prototype/rls-isolation` @ 21dd919).
- Single server chokepoint: verified Clerk session → `owners.external_id` → `owner_id` → `SET LOCAL` inside txn. Agent tools never accept Owner identity ([#11](https://github.com/tonismonis/agent/issues/11)).
- HAZARD (must-test): `SET LOCAL` outside txn = silent no-op = silent RLS bypass. Ship an integration test against a *pooled* endpoint w/ 2 concurrent Owners ([#12](https://github.com/tonismonis/agent/issues/12)). Transaction-mode pooling itself is safe.

## Data model

Fixed schema, data ops only — agent never does DDL. Whole-CLP integer money, tz hardcoded America/Santiago, `now()` injected per-request in prompt ([#6](https://github.com/tonismonis/agent/issues/6), [#7](https://github.com/tonismonis/agent/issues/7)).

- `owners` — id, external_id (null till first login), email, name, profession (feeds system prompt), restricted_notes bool, timestamps ([#7](https://github.com/tonismonis/agent/issues/7)).
- `clients` — name required, contacts optional, notes, soft delete.
- `services` — price × unit (`hour`|`flat`), `duration_minutes` nullable, soft delete.
- `appointments` — client+service FKs, starts/ends (ends computed host-side), mode online|in_person, status scheduled|completed|cancelled|no_show, price snapshot host-computed w/ override param, notes. Overlap = reject at tool w/ conflict detail ([#6](https://github.com/tonismonis/agent/issues/6)).
- `payments` — nullable appointment_id, paid_at, notes. Revenue-collected = Σ payments; revenue-earned = Σ completed appointments.
- `working_hours` — (owner_id, weekday, start, end), CHECK start<end, exclusion constraint vs overlap; no rows = day off ([#7](https://github.com/tonismonis/agent/issues/7)).
- `audit_log` — append-only, every agent write (tool, input, entity+id, before, ok/error, ts); reads not logged; kept for Owner lifetime ([#5](https://github.com/tonismonis/agent/issues/5)).
- Chat persistence tables: `messages` + `runs` per `@tanstack/ai-persistence` drizzle/pg adapter ([#8](https://github.com/tonismonis/agent/issues/8)).

Soft delete + `restore_*` everywhere; cancel = status, not delete; `delete_client` rejects on future appointments ([#5](https://github.com/tonismonis/agent/issues/5)).

## Agent + tools

Baseline = 21 prototype tools (`crm/src/lib/tools.server.ts`): CRUD + find + softDelete + restore per table, `listAuditLog`. v1 adds ([#7](https://github.com/tonismonis/agent/issues/7)):

- `set_working_hours` — transactional row replace.
- `find_free_slots` — SQL: working-hours ranges minus appointments; input date range + duration. Agent may only suggest slots this tool returns.
- `update_owner_profile` — name only. Operator-only fields: email, profession, restricted_notes. No agent tool may ever touch `restricted_notes`.

Behavior rules (prompt-owned, per [#4](https://github.com/tonismonis/agent/issues/4)/[#5](https://github.com/tonismonis/agent/issues/5)):
- Writes execute immediately, no approval gates; safety = audit log + soft deletes.
- Clarify-first on ambiguous utterances.
- Undo = conversational: `listAuditLog` + `restore_*`; `restore_appointment` re-checks overlap.
- Never store health/personal context in any field; payments.notes = payment method/ref only.

## Chat persistence + inference cap

([#8](https://github.com/tonismonis/agent/issues/8), doc [tanstack-ai-persistence.md](../research/tanstack-ai-persistence.md))

- Server: `withPersistence` + drizzle/pg, same Postgres; messages+runs only (`runs` token usage → per-Owner spend query). Skip interrupts, resumable streams, ai-memory.
- Client: `persistence: true`, server-authoritative, `snapshotStreaming` off.
- Inference cap = daily thread rotation (`day-YYYY-MM-DD`, Santiago tz). No compaction v1; cross-day continuity = agent queries db + audit log. Old threads kept forever.
- Per-Owner metering + hard limit on the central OpenRouter key.

## Model + inference

- Default `anthropic/claude-haiku-4-5`, one-string swappable ([#4](https://github.com/tonismonis/agent/issues/4)).
- `openai/gpt-oss-120b` DROPPED — ZDR filter useless (all 19 hosts flagged) ([#13](https://github.com/tonismonis/agent/issues/13)).
- A/B candidate: `openai/gpt-5.6-luna` (~$0.20/$1.20 per Mtok, ~5-8x cheaper than haiku; operator input 2026-08-01 on [#10](https://github.com/tonismonis/agent/issues/10)). Gate before adoption: (a) passes crm 27-test suite + `crm/ab-utterances.md`, (b) ZDR routing check same rigor as #13 (pinnable providers, retention), (c) watch intro-pricing throttles / quantized serving.
- OpenRouter config (locked, [#13](https://github.com/tonismonis/agent/issues/13)): account-wide ZDR on, both logging toggles OFF, no plugins; per-request `provider: { zdr: true, data_collection: "deny", only: ["google-vertex","amazon-bedrock"], allow_fallbacks: true }`; opaque UUID as `user`. Passed via `modelOptions.provider`.

## Sensitive-data boundary

([#13](https://github.com/tonismonis/agent/issues/13), [#15](https://github.com/tonismonis/agent/issues/15)) — OpenRouter DPA prohibits sensitive-category data; v1 condition: no health-adjacent free-text reachable by agent, enforced by product design:

- Schema identical for all; `owners.restricted_notes` flag, operator-set at invite for health-adjacent professions.
- Flag on → ALL notes columns dark: server tool layer rejects writes, excludes on reads. + one prompt line.
- Rule comms = operator personally at invite ([#7](https://github.com/tonismonis/agent/issues/7)).
- Accepted residuals: Owner typing clinical text into chat; incidental Art. 9-adjacent notes by unrestricted Owners.

## Auth + onboarding

([#7](https://github.com/tonismonis/agent/issues/7), [#11](https://github.com/tonismonis/agent/issues/11))

- Invite = one operator act: Clerk invitation + pre-created Owner row (email, name, profession, restricted_notes). First verified session matches by email, stamps `external_id`.
- Onboarding UX deferred; operator onboards personally.
- Offboarding = Owner purge: app cascade + Clerk user delete; operator-only, never an agent tool.

## Out of scope (post-v1)

Calendars/dashboards/visualizer pages; local-only clinical notes (IndexedDB escape hatch, [#15](https://github.com/tonismonis/agent/issues/15)); group classes, packages, recurrence table, payment methods, payer≠attendee; working-hours exceptions/vacations; approval gates; compaction/summarization; resumable streams; BYOK; onboarding UX; user bans (Clerk Pro).
